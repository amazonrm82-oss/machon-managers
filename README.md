# מכון פוירשטיין

שתי המערכות של המכון, מאחורי עמוד בחירה אחד.

```
פתיחת האפליקציה
        │
        ▼
   index.html            בחירה: למידה או ניהול
        │
        ├── learn.html   מערכת הלמידה  → התחברות עם Microsoft 365 של המכון
        │
        └── manage.html  מערכת הניהול  → התחברות עם סיסמת תפקיד
```

## הקבצים

| קובץ | מה זה |
| --- | --- |
| `index.html` | עמוד הבחירה — הלוגו, ושני כרטיסים: למידה / ניהול |
| `learn.html` | מערכת הלמידה (נבנה מ-`learn-src/` — לא לערוך ידנית) |
| `manage.html` | מערכת ניהול התפעול הארצי |
| `projects.html` | ניהול פרויקטים (נפתח מתוך מערכת הניהול) |
| `ms-config.js` | הגדרות ההתחברות ל-Microsoft — ניתן לעריכה בלי בנייה מחדש |
| `logo.svg` | הלוגו — שרטוט וקטורי לפי הלוגו של המכון |
| `learn-src/` | המקור של מערכת הלמידה + הוראות הגדרת ההתחברות |
| `supabase/` | פונקציות השרת של מערכת הניהול |

## הלוגו

`logo.svg` הוא שרטוט וקטורי של הלוגו — עיגול בארבעת צבעי המכון עם צללית
הפרופיל. הוא משמש בכותרת עמוד הבחירה, במסך ההתחברות ללמידה, כסימן מים
ברקע, וכבסיס לאייקוני האפליקציה.

**זהו שחזור ידני, לא קובץ המקור הרשמי.** אם יש בידכם את קובץ הלוגו
המקורי, החלפת `logo.svg` בו תעדכן את כל המקומות האלה בבת אחת. לרענון
האייקונים אחרי החלפה: `node build-icons.mjs`.

## בנייה

`learn.html` נבנה מ-`learn-src/`. הבנייה רצה אוטומטית בפריסה, ולפיתוח מקומי:

```bash
node build-learn.mjs
python3 -m http.server 8080     # ואז http://localhost:8080
```

`index.html`, `manage.html` ו-`projects.html` נערכים ישירות.

## פריסה

דחיפה ל-`main` מפעילה את `.github/workflows/deploy.yml`, שבונה את
`learn.html` ומפרסם את האתר ל-GitHub Pages.

## שתי מערכות, שרת אחד, בלי לפגוע אחת בשנייה

שתי המערכות יושבות על אותו פרויקט Supabase — אבל אין ביניהן שום נקודת מגע.

| | ניהול | למידה |
| --- | --- | --- |
| טבלאות | `app_state`, `role_passwords` | `learning_state`, `learning_submissions`, `learning_roles`, `learning_assets` |
| שער כניסה | `app-state-gateway` | `learning-gateway` |
| התחברות | סיסמת תפקיד (`role-auth`) | חשבון Microsoft של המכון |
| מה מאמת את הזהות | חתימה עם `AUTH_TOKEN_SECRET` | המפתחות הציבוריים של Microsoft |

**מה זה אומר בפועל:** בקוד של `learning-gateway` אין אף שורה שמזכירה
`app_state`. גם אם תתגלה שם תקלה, וגם אם מישהו ישיג טוקן של עובד — אין
דרך להגיע לנתוני התפעול של המכונים. וההפך: `app-state-gateway` לא מכיר
טוקנים של Microsoft, ומערכת הניהול לא נוגעת בטבלאות הלמידה.

RLS על טבלאות הלמידה מוגדר **בלי אף policy**, כלומר anon חסום לגמרי —
רק ה-Edge Function, שמשתמש ב-service_role, נכנס.

**הרשאות בתוך הלמידה:** עובד רואה וכותב רק את התיק שלו. מנהל ישיר רואה
את הצוות שלו וכותב משוב. רכז הדרכה רואה את כל הסניפים. חשבון שלא סווג
מקבל את ההרשאה הנמוכה ביותר — עובד.

### הפעלה

השכבה הזו כתובה אבל **עדיין לא נפרסה** — היא ממתינה לרישום ב-Entra ID.
כשיהיה:

```bash
supabase db push                                    # יוצר את טבלאות הלמידה
supabase secrets set MS_TENANT_ID=... MS_CLIENT_ID=...
supabase functions deploy learning-gateway
```

עד אז מערכת הלמידה שומרת הכל בדפדפן של המשתמש — לא הולך לאיבוד, אבל
מנהל לא רואה את המבחן של העובד. זה השינוי היחיד שהפריסה הזו עושה.

## הזנת התוכן

רכז ההדרכה מזין הכל מתוך המערכת — אין תוכן שמחייב שינוי קוד:

| מסך | מה מזינים |
| --- | --- |
| בניית תוכנית הלימודים | שלבים, פרקים, מסלולי אגפים, תנאי התעודה, מחסן שאלות כללי ומחסן המבחן המסכם |
| תוכן הפרק | תיאור, אורך, קישור לווידאו, ״מה בפרק״, חומרים מצורפים, ומחסן שאלות ייעודי לפרק |
| ניהול השיעורים | לוח שיעורי ההעשרה — תאריך, שעה, מרצה, קהל, שעות המשך, קישור Zoom |
| ניהול מאגר הידע | נכסי הידע — כותרת, תיאור, נושא, סוג וקישור |

הגישה: **ניהול → מסך רכז ההדרכה**.

לפרק שאין לו שאלות משלו נשלף המבחן מהמחסן הכללי, כך שהמערכת עובדת מהיום
הראשון. ברגע שמוסיפים לפרק שאלה אחת — הוא עובר להשתמש רק בשלו.

כל אחד מהמסכים האלה מגיע עם תוכן התחלתי וכפתור חזרה אליו.

## התחברות

- **ניהול** — סיסמת תפקיד, נבדקת בפונקציית `role-auth` בסופאבייס.
  הפרטים ב-`SECURITY_FIX_README.md`.
- **למידה** — חשבון Microsoft 365 של המכון (Entra ID). הגדרה חד-פעמית
  לפי `learn-src/README.md`; עד שתתבצע, מסך ההתחברות מציג כניסת דמו
  מסומנת במפורש.
